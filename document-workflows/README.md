# IFRS document workflow sidecar

This is a separate authenticated document tool channel. It does not change `agentBinding`, numeric response mapping, native regions, bounded nominal token semantics, PRECEDENCE/MAX or advise-only PE autonomy. The canonical Machines catalog supplies 68 owned document types and their dependency DAG. Generated agent facets preserve existing native analyst fields; template/runbook/asset references are validated during generation.

`service.py` adapts the Machines lifecycle rules to transactional SQLite storage. Immutable revisions, CAS heads, downstream invalidation, task outbox, contributions and dispatch receipts commit together. A process failure rolls back the transaction. Retries with the same dispatch ID and body return the committed receipt; a changed body with that ID fails. Inspection always reads current state. Entity/period and source/fact/policy/index context are pinned by a separately authorized operator.

Agents may inspect, retrieve, calculate narrow declared controls, contribute, draft owned assets, resolve owned assessments and request independent review. Only an explicitly configured reviewer principal can approve/reject its assigned exact revision. Agent tokens cannot approve or assert verified input changes. Reviewer names come from the authenticated credential mapping, not an LLM payload. Monetary values require decimal strings, currency and date; calculation facts come from the current operator-pinned context. The limited eligibility/contract-cost controls return advisory determinations and never automatically select native branches. Unknown controls/data/other-section exceptions remain unresolved.

Configure private credentials outside Git: `IFRS_WORKFLOW_PRINCIPALS` points to a 0600 JSON list of unique `name`, `role` (`agent`, `reviewer`, `operator`, `projection`), `token`, and allowed `scopes` (`[[entityId, period]]`). Agent principals also name a canonical `machineId`; permissions are derived server-side from its family and catalog. Configure `IFRS_ASSETS_DIR`, `IFRS_MACHINES_DIR`, `IFRS_DOCUMENT_STATE_DIR`, `IFRS_RAG_URL` and `IFRS_EVIDENCE_TOKEN`. Install pinned `requirements.txt` in a dedicated interpreter, set `IFRS_PYTHON`, then run `scripts/start-ifrs-workflows.sh`. It binds loopback only.

POST `/tools/execute` with a Bearer credential and `{dispatchId, operation, context, arguments}`. An operator first sends `event` with a period/facts/source/policy event and applicable asset IDs, pinning context. Agent operations include `tasks`, `resource`, `retrieve`, `inspect`, `observe`, `contribute`, `draft`, `calculate`, `request-review`, `resolve-assessment`. Reviewer operations `approve`/`reject` require exact revision/hash. Approval retrieves and verifies the cited RAG interaction/current index independently. Final statement/compliance assets require no unresolved accounting requirements. No posting, filing, signing or release operation exists.

The durable task outbox routes accountability by family; structured contributions also retain the source machine and explicit target steward from `accounting-workflow-graph.json`. The `tasks` tool exposes open/scoped owned work and contributions. Native recognizer observations queue assessment only; verified impact is a distinct operation. Artifact projection uses the read-only `export`/`inspect` boundary, not a second document owner. Local event sequence numbers order store updates; they do not create a new engine Lamport-clock participant.

Install `plugins/ifrs-documents` through OpenClaw's explicit local plugin path. Its manifest declares optional `ifrs_document_workflow`. Set `plugins.entries.ifrs-documents.config.configurationFile` to a 0600 operator-managed JSON file containing `url` and `agents: {<trusted gateway agentId>: {token, context}}`; explicitly allow the tool only for intended agents. The factory uses trusted runtime agent identity. Model arguments cannot select credentials, context, another agent, approval or release. Keep each task in a fresh gateway session. Credentials never enter model prompts/tool results. For an installed deployment use its normal reviewed plugin installation/configuration process; the CI proof uses a private gateway/state directory and does not rewrite the user's running gateway.

The user's requested synthetic package lives in the canonical Machines domain under `acceptance/synthetic`. Synthetic review credentials are test principals, not evidence of an actual accounting professional's review. Keep synthetic storage and provenance distinct from actual issuer records. `RealityEngine_CI/scripts/verify-ifrs-workflows.py` deploys the connectors, uses real local embeddings, checks all 38 supplied source sections, exercises seven synthetic controls/reconciliations and the lifecycle, and optionally proves a real gateway/model tool call. The narrow proof does not close the domain-wide accounting findings, verify detached source labels, establish native parity or approve the domain.

Use `scripts/configure-ifrs-workflows.py` with the active operator-pinned context, candidate Machines root, private state directory and connector/gateway URLs to materialize all IFRS agent credentials, 68 asset routes and a reviewable plugin patch. Existing private credentials are retained. Merge the optional tool into the gateway's existing allow/alsoAllow policy deliberately; OpenClaw forbids setting both in the same scope. The command does not modify the running gateway.

Run `document-workflows/worker.py --config <private-worker.json> --limit 1` to claim canonical open tasks and dispatch them in fresh gateway sessions. Concurrent workers use expiring SQLite leases; CAS/idempotency remain enforced by the canonical sidecar. A model-only claim of success is recorded as unresolved. Only a changed canonical artifact is reported as observed work, and independent review remains required. Evidence references must belong to the operator-pinned entity/period; a foreign record or stale context is rejected. Contributions are content-deduplicated, route to their named steward, become superseded on relevant drift, and can be satisfied only by an exact approved artifact that cites them.

The preferred model-facing tools have explicit flat schemas: `ifrs_document_inspect`, `ifrs_document_resource`, `ifrs_source_retrieve`, `ifrs_document_draft`, `ifrs_document_tasks`, `ifrs_accounting_calculate`, and `ifrs_document_request_review`, with separate contribution/assessment tools. `ifrs_document_workflow` remains a compatibility adapter. Compact resource responses expose template/control IDs; fetch runbooks or chosen controls explicitly rather than loading an entire family corpus into every task. The source service verifies newly retrieved receipt IDs independently before they can be cited in a draft. Immutable revisions retain their evidence class; an agent cannot relabel synthetic content as actual evidence.

Unresolved model attempts are retried at most three times per selected task by default (`--max-attempts`, maximum five), in fresh sessions with the same authorization/CAS/artifact checks. Every failure stays in the attempt ledger. Narrative success without a changed canonical artifact is never completion; after exhaustion the task remains unresolved.
